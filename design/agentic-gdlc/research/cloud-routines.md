Resolves [#234](https://github.com/justinclayton/nvu-game/issues/234). Facts only, each with its
primary source. Gathered 2026-10-01. Routines are in research preview; Anthropic says behavior,

## Creating, scheduling, and triggering on demand

- A routine is "a saved Claude Code configuration: a prompt, one or more repositories, and a set of connectors, packaged once and run automatically", run on Anthropic-managed cloud infrastructure. ([routines](https://code.claude.com/docs/en/routines))
- Three trigger types, combinable on one routine: **Scheduled** (recurring or one-off), **API** ("an HTTP POST to a per-routine endpoint with a bearer token"), **GitHub** (pull request and release events). ([routines](https://code.claude.com/docs/en/routines))
- Created from the web at claude.ai/code/routines, from the Desktop app (Code tab > Routines > New routine > Cloud), or from the CLI with `/schedule` (alias `/routines`). All three write to the same cloud account. ([routines: Create a routine](https://code.claude.com/docs/en/routines#create-a-routine))
- Schedule presets: hourly, daily, weekdays, weekly, or a one-off timestamp. Custom cron is set via `/schedule update` in the CLI; "The minimum interval is one hour; expressions that run more frequently are rejected." Runs set exactly on the hour "can start several minutes late". ([routines: Add a schedule trigger](https://code.claude.com/docs/en/routines#add-a-schedule-trigger))
- On-demand start, three ways: (1) **Run now** button on the routine's web detail page, optionally with run-specific text; (2) `/schedule run` in the CLI; (3) `POST https://api.anthropic.com/v1/claude_code/routines/{trig_...}/fire` with `Authorization: Bearer sk-ant-oat01-...` and `anthropic-version: 2023-06-01`. ([routines: Edit and control](https://code.claude.com/docs/en/routines#edit-and-control-routines), [Manage from CLI](https://code.claude.com/docs/en/routines#manage-routines-from-the-cli), [Platform: routines-fire](https://platform.claude.com/docs/en/api/claude-code/routines-fire))
- API triggers can only be added, and tokens generated/revoked, from the web UI: "The CLI cannot currently create or revoke tokens." "There is no public API for token management." Token is shown once; regenerating revokes the previous one. ([routines: Add an API trigger](https://code.claude.com/docs/en/routines#add-an-api-trigger), [Platform: Authentication](https://platform.claude.com/docs/en/api/claude-code/routines-fire#authentication))
- The fire request "returns once the session is created. It does not stream session output or wait for the session to complete." Response: `{"type":"routine_fire","claude_code_session_id":"session_...","claude_code_session_url":"https://claude.ai/code/session_..."}`. ([Platform: routines-fire](https://platform.claude.com/docs/en/api/claude-code/routines-fire))
- Request body: optional `text`, freeform, max 65,536 characters, not parsed (JSON arrives as a literal string). It reaches the session wrapped in a `<routine-fire-payload>` block labelled untrusted; the routine's saved prompt must explicitly reference the payload for Claude to act on it. Same wrapping applies to **Run now** text. ([routines: Trigger a routine](https://code.claude.com/docs/en/routines#trigger-a-routine))
- No idempotency key: "If a webhook caller retries, the endpoint creates multiple sessions." ([Platform: Idempotency](https://platform.claude.com/docs/en/api/claude-code/routines-fire#idempotency))
- Error codes: 400 (bad `anthropic-version`, `text` too long, or routine paused), 401 (missing/mismatched token), 403 (no access), 404, 429 (hourly limit; `Retry-After` header), 500, 503. ([Platform: Errors](https://platform.claude.com/docs/en/api/claude-code/routines-fire#errors))
- The `/fire` endpoint "is available to claude.ai users only and is not part of the Claude Platform API surface"; not in any SDK. ([routines: API reference](https://code.claude.com/docs/en/routines#api-reference), [Platform: SDK support](https://platform.claude.com/docs/en/api/claude-code/routines-fire#sdk-support))
- The Platform doc shows a GitHub Actions step calling the fire endpoint with `curl` and secrets `ROUTINE_FIRE_URL` / `ROUTINE_FIRE_TOKEN`. ([Platform: Trigger a routine](https://platform.claude.com/docs/en/api/claude-code/routines-fire#trigger-a-routine))
- No `gh` subcommand starts a routine; the GitHub-native path is a GitHub trigger on `pull_request.*` or `release.*` events, filtered by author, title, body, base/head branch, labels, draft, merged (operators: equals, contains, starts with, is one of, is not one of, matches regex). Requires the Claude GitHub App installed on the repo. Webhook events "are subject to per-routine and per-account hourly caps. Events beyond the limit are dropped". ([routines: Add a GitHub trigger](https://code.claude.com/docs/en/routines#add-a-github-trigger))
- A new interactive cloud session can also be prefilled from a URL: `https://claude.ai/code?prompt=...&repositories=owner/repo&environment=...`; this opens the form, it does not start a run. ([web quickstart: Pre-fill sessions](https://code.claude.com/docs/en/web-quickstart#pre-fill-sessions))
- A one-off scheduled routine auto-disables after firing and shows **Ran**; "To run it again, edit the routine and set a new one-off time." ([routines: Schedule a one-off run](https://code.claude.com/docs/en/routines#schedule-a-one-off-run))
- Routines "belong to your individual claude.ai account. They are not shared with teammates". ([routines: Create a routine](https://code.claude.com/docs/en/routines#create-a-routine))

## Repo access

- Each selected repository "is cloned at the start of a run, starting from the default branch. Claude creates `claude/`-prefixed branches for its changes." "Claude starts from the repository's default branch unless your prompt specifies otherwise." ([routines: Select repositories](https://code.claude.com/docs/en/routines#create-from-the-web), [Repositories and branch permissions](https://code.claude.com/docs/en/routines#repositories-and-branch-permissions))
- Pushes to `claude/`-prefixed branches "are always accepted". A push to any other branch is rejected if the branch is protected on GitHub, someone else has an open PR from it, or it carries commits authored by someone other than you. ([routines: Repositories and branch permissions](https://code.claude.com/docs/en/routines#repositories-and-branch-permissions))
- GitHub proxy "Push protection: `git push` works only against the session's current working branch; cloning, fetching, and PR operations work normally." ([cloud environments: GitHub proxy](https://code.claude.com/docs/en/cloud-environments#github-proxy))
- Commits and PRs "carry your GitHub user" (the account that connected GitHub). Cloud-session commits include a `Claude-Session: <url>` git trailer and PR bodies include the session URL (disable with `attribution.sessionUrl: false`). ([routines: Create a routine](https://code.claude.com/docs/en/routines#create-a-routine), [cloud environments: Link output back](https://code.claude.com/docs/en/cloud-environments#link-output-back-to-the-session))
- Built-in GitHub tools "let Claude read issues, list pull requests, fetch diffs, and post comments without any setup", authenticated through the GitHub proxy. `gh` CLI is pre-installed and works without `gh auth login`; `GH_TOKEN`/`GITHUB_TOKEN` read as the placeholder `proxy-injected` unless you set a real token as an environment variable. ([cloud environments: Work with GitHub issues and PRs](https://code.claude.com/docs/en/cloud-environments#work-with-github-issues-and-pull-requests))
- Proxy repository scope: "GitHub API and release-asset requests reach only repositories attached to the session, so a setup script that downloads release assets from an unattached repository gets a 403." ([cloud environments: GitHub proxy](https://code.claude.com/docs/en/cloud-environments#github-proxy))
- Proxy GraphQL restriction: only "a pinned set of GraphQL operations for pull-request workflows"; everything else gets 403 with a REST fallback hint; Projects v2 is unreachable. Applies even with your own `GH_TOKEN`. ([cloud environments: GitHub proxy](https://code.claude.com/docs/en/cloud-environments#github-proxy))
- Two GitHub auth methods: Claude GitHub App (public repos plus private repos the app is installed on) or `/web-setup` (sends your local `gh auth token` to Anthropic; sessions reach any repo that token can). Credentials "stay encrypted on Anthropic's servers and never enter a session's VM". ([cloud sessions: GitHub authentication options](https://code.claude.com/docs/en/claude-code-on-the-web#github-authentication-options))
- If the GitHub connection is missing when a run is due, the routine skips runs for up to 72 hours, then turns off. ([routines: Repositories and branch permissions](https://code.claude.com/docs/en/routines#repositories-and-branch-permissions))
- The GitHub App page (github.com/apps/claude) does not list its permission scopes; description: "Run Claude Code from your GitHub Pull Requests and Issues to respond to reviewer feedback, fix CI errors, or modify code". ([GitHub App page](https://github.com/apps/claude))
- Actions artifacts over the REST API: `GET /repos/{owner}/{repo}/actions/runs/{run_id}/artifacts` and `GET /repos/{owner}/{repo}/actions/artifacts/{artifact_id}/{archive_format}` need `"Actions" repository permissions (read)` for fine-grained tokens, or `repo` scope for classic tokens; the download returns a 302 to a URL that expires after 1 minute. Listing "can be used without authentication ... if only public resources are requested". ([GitHub REST: Artifacts](https://docs.github.com/en/rest/actions/artifacts?apiVersion=2022-11-28))
- `gh run download RUN_ID [-n ARTIFACT_NAME]` downloads artifacts; "Read access to the repository is required". Default retention is 90 days (public repos adjustable 1–90 days, private 1–400). ([GitHub: Download workflow artifacts](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/download-workflow-artifacts), [GitHub: Retention period](https://docs.github.com/en/organizations/managing-organization-settings/configuring-the-retention-period-for-github-actions-artifacts-and-logs-in-your-organization))
- Issue comments: `POST /repos/{owner}/{repo}/issues/{issue_number}/comments` needs `"Issues"` or `"Pull requests"` repository permissions (write). PR creation: `POST /repos/{owner}/{repo}/pulls` needs `"Pull requests"` repository permissions (write). ([GitHub REST: Issue comments](https://docs.github.com/en/rest/issues/comments?apiVersion=2022-11-28), [GitHub REST: Pulls](https://docs.github.com/en/rest/pulls/pulls?apiVersion=2022-11-28))
- Session with one repository reads the repo's `CLAUDE.md`, `.claude/settings.json` hooks and permission rules, `.claude/rules/`, `.claude/skills|agents|commands/`, and `.mcp.json`. A multi-repository session "starts above the clones and doesn't read" settings or `.mcp.json`. Plugins declared in repo settings are not installed. ([cloud environments: What carries over](https://code.claude.com/docs/en/cloud-environments#what-carries-over-from-your-setup))

## Permission mode and what it cannot do

- Routines "run autonomously as full Claude Code cloud sessions: there is no permission-mode picker, and the session runs shell commands, uses skills committed to the cloned repository, and calls any connectors you include, all without stopping for approval apart from some artifact actions." ([routines: Create a routine](https://code.claude.com/docs/en/routines#create-a-routine))
- Included connectors: "Claude can use every tool from an included connector, including writes, without asking for permission during a run." All connected connectors are included by default. ([routines: Review connectors](https://code.claude.com/docs/en/routines#create-from-the-web))
- Interactive cloud sessions offer Accept edits, Plan, and Auto; "Cloud sessions don't offer Manual or Bypass permissions." Repo settings `defaultMode: "bypassPermissions"` or `"dontAsk"` are ignored silently. ([web quickstart: Choose a permission mode](https://code.claude.com/docs/en/web-quickstart#start-a-task), [permission modes: bypassPermissions](https://code.claude.com/docs/en/permission-modes#skip-all-checks-with-bypasspermissions-mode))
- Each session is "an isolated, Anthropic-managed VM" running Ubuntu 24.04 x86_64; approximate ceilings 4 vCPUs, 16 GB RAM, 30 GB disk. "You don't get a shell into the session VM. Claude runs every command for you." ([cloud sessions: Security and isolation](https://code.claude.com/docs/en/claude-code-on-the-web#security-and-isolation), [cloud environments: Resource limits](https://code.claude.com/docs/en/cloud-environments#resource-limits), [Run tests](https://code.claude.com/docs/en/cloud-environments#run-tests-start-services-and-add-packages))
- Network: four levels, None / Trusted / Full / Custom. **Default** environment is Trusted: "allows only the default allowlist of package registries, cloud provider APIs, container registries, and common development domains". Other hosts fail with `403` and `x-deny-reason: host_not_allowed`. GitHub (via proxy), MCP connectors (via Anthropic), API-credential hosts, and the Anthropic API bypass the allowlist. ([cloud environments: Access levels](https://code.claude.com/docs/en/cloud-environments#access-levels), [routines: Environments and network access](https://code.claude.com/docs/en/routines#environments-and-network-access))
- The Trusted allowlist includes `registry.npmjs.org`, `github.com`, `api.github.com`, `raw.githubusercontent.com`, `objects.githubusercontent.com`, `release-assets.githubusercontent.com`, `archive.ubuntu.com`, `security.ubuntu.com`, `*.ubuntu.com`, `ppa.launchpad.net`, `storage.googleapis.com`, `*.googleapis.com`, `fonts.googleapis.com`, `fonts.gstatic.com`, Docker Hub hosts. ([cloud environments: Default allowed domains](https://code.claude.com/docs/en/cloud-environments#default-allowed-domains))
- All outbound traffic passes through a security proxy (content filtering, rate limiting, DNS audit trail). ([cloud environments: Security proxy](https://code.claude.com/docs/en/cloud-environments#security-proxy))
- Secrets: environment variables "are visible to anyone who uses the environment"; the docs warn against putting secrets there. On Pro and Max, **API credentials** are attached by Anthropic's agent proxy to requests for listed hosts and "never reach Claude, the commands it runs, or the session's environment variables". Not available on Team/Enterprise. Never attached to GitHub, `api.anthropic.com`, public package registries, or setup-script requests. ([cloud environments: Add API credentials](https://code.claude.com/docs/en/cloud-environments#add-api-credentials))
- No interactive auth ("SSO requires browser-based login that can't run in a cloud session"). ([cloud environments: What carries over](https://code.claude.com/docs/en/cloud-environments#what-carries-over-from-your-setup))
- Cloud sessions "set `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE` themselves"; `/clear` unavailable; subagents work; agent teams off unless `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`. ([cloud sessions: Manage context](https://code.claude.com/docs/en/claude-code-on-the-web#manage-context))
- Hooks from the repo's `.claude/settings.json` run (single-repo sessions); SessionStart `command` hooks are cancelled after 600 s unless `timeout` is set. The VM exposes `CLAUDE_CODE_REMOTE=true` and `CLAUDE_CODE_REMOTE_SESSION_ID`. ([cloud environments: Setup scripts vs SessionStart hooks](https://code.claude.com/docs/en/cloud-environments#setup-scripts-vs-sessionstart-hooks), [Time limits](https://code.claude.com/docs/en/cloud-environments#time-limits))
- A green run status "means the session started and exited without an infrastructure error. It does not mean the task in your prompt succeeded." ([routines: View and interact with runs](https://code.claude.com/docs/en/routines#view-and-interact-with-runs))
- Prompts fired by a trigger are treated as the assigned task (since v2.1.213); earlier versions framed them as untrusted and could refuse. ([routines: Name the routine and write the prompt](https://code.claude.com/docs/en/routines#create-from-the-web))

## Limits: run length, concurrency, usage accounting

- Hourly start limits (no overage on any): scheduled runs incl. one-off, 100/hour per account (run waits); **Run now** + API fires + one-off re-arm, 30/hour per routine (shared count; action fails); **Run now** + re-arm, 100/hour per account; API fires, 100/hour per account, counted separately from Run now. ([routines: Usage and limits](https://code.claude.com/docs/en/routines#usage-and-limits))
- The launch post (2026-04-14) stated daily caps: "Pro users get 5 routines daily; Max users receive 15 daily; Team and Enterprise users access 25 daily", with more via extra usage. The current routines doc lists only the hourly limits above and no daily cap. ([blog: Introducing routines](https://claude.com/blog/introducing-routines-in-claude-code), [routines: Usage and limits](https://code.claude.com/docs/en/routines#usage-and-limits))
- "Routines draw down subscription usage the same way interactive sessions do." Billing column for the fire endpoint: "Claude Code subscription usage on claude.ai", versus "Claude Platform usage" for API-key use. ([routines: Usage and limits](https://code.claude.com/docs/en/routines#usage-and-limits), [Platform: Differences](https://platform.claude.com/docs/en/api/claude-code/routines-fire#differences-from-the-claude-platform))
- "Cloud sessions share rate limits with all other Claude and Claude Code usage within your account. Running multiple tasks in parallel consumes more rate limits proportionately. There is no separate compute charge for the cloud VM." ([cloud sessions: Limitations](https://code.claude.com/docs/en/claude-code-on-the-web#limitations))
- Routines require a claude.ai subscription login (Pro, Max, Team, Enterprise); `/schedule` is hidden with a Console API key, Bedrock/Vertex/Foundry, or when `ANTHROPIC_API_KEY` is set. Routines cannot run on an API key. ([routines: Troubleshooting](https://code.claude.com/docs/en/routines#troubleshooting))
- When the subscription limit is hit: with usage credits on, routines continue on metered overage; without, "additional runs are rejected until your usage window resets". Usage credits "are billed at standard API rates"; Pro and Max can enable them at claude.ai/settings/usage; daily redemption limit $2000. Prompt-cache lifetime drops from one hour to five minutes while on usage credits. ([routines: Usage and limits](https://code.claude.com/docs/en/routines#usage-and-limits), [support: Extra usage](https://support.claude.com/en/articles/12429409-extra-usage-for-paid-claude-plans), [costs: Why usage climbs](https://code.claude.com/docs/en/costs#why-usage-climbs-in-a-long-session))
- Max plans have a five-hour session limit and a weekly limit across all models; Max 5x = 5x and Max 20x = 20x Pro's per-session allowance. ([support: What is the Max plan](https://support.claude.com/en/articles/11049741-what-is-the-max-plan))
- While a subscription is paused, routines are put on hold. ([routines: Usage and limits](https://code.claude.com/docs/en/routines#usage-and-limits))
- Command time limits: Bash foreground default 2 minutes, up to 10 minutes on request; a timed-out command moves to the background for up to 30 more minutes; raise with `BASH_DEFAULT_TIMEOUT_MS` / `BASH_MAX_TIMEOUT_MS` environment variables. Setup script must finish in roughly five minutes to be cached. Idle VMs pause "after a few minutes without activity" and can be reclaimed. ([cloud environments: Time limits](https://code.claude.com/docs/en/cloud-environments#time-limits))
- Concurrency: each trigger match creates a new session; "Claude Code doesn't reuse sessions across events, so two PR updates produce two independent sessions." Each `--cloud` or run is its own session that runs independently. ([routines: Add a GitHub trigger](https://code.claude.com/docs/en/routines#add-a-github-trigger), [cloud sessions: Run tasks in parallel](https://code.claude.com/docs/en/claude-code-on-the-web#tips-for-cloud-tasks))
- Organization IP allowlisting breaks Anthropic-hosted routines with an authentication error. ([cloud sessions: Limitations](https://code.claude.com/docs/en/claude-code-on-the-web#limitations))

## Calling `make` targets (Node 20+, npm, headless Chrome)

- Pre-installed: Node.js 20, 21, and 22 (at `/opt/node20`, `/opt/node21`, `/opt/node22`; 22 on `PATH` by default) with npm, yarn, pnpm, bun, eslint, prettier, chromedriver; GCC, Clang, cmake, ninja; git, gh, jq, yq, ripgrep; Docker; Python, Ruby, PHP, Java, Go, Rust. `check-tools` on the VM prints versions. ([cloud environments: Installed tools](https://code.claude.com/docs/en/cloud-environments#installed-tools))
- Setup scripts "run as root on Ubuntu 24.04, so `apt install` and most language package managers work"; `archive.ubuntu.com`, `security.ubuntu.com`, `ppa.launchpad.net` are on the Trusted allowlist. The filesystem after a successful (<~5 min) setup script is snapshotted and reused for about seven days or until the script/allowlist changes. ([cloud environments: Setup scripts](https://code.claude.com/docs/en/cloud-environments#setup-scripts), [Environment caching](https://code.claude.com/docs/en/cloud-environments#environment-caching))
- `storage.googleapis.com` and `*.googleapis.com` are on the Trusted allowlist. ([cloud environments: Default allowed domains](https://code.claude.com/docs/en/cloud-environments#default-allowed-domains))
- Recommended pattern for `npm install` is a repo SessionStart hook gated on `CLAUDE_CODE_REMOTE=true`; it runs every session (no caching) and only in single-repo sessions. ([cloud environments: Install dependencies with a SessionStart hook](https://code.claude.com/docs/en/cloud-environments#install-dependencies-with-a-sessionstart-hook))
- Bun "has known proxy compatibility issues for package fetching" behind the security proxy. ([cloud environments: Installed tools](https://code.claude.com/docs/en/cloud-environments#installed-tools))
- Replacing the base image "isn't supported yet"; customize via setup script or a `docker compose` sidecar. ([cloud environments: Limitations in cloud sessions](https://code.claude.com/docs/en/cloud-environments#limitations-in-cloud-sessions))

## Not established

- Whether `make` (GNU Make / build-essential) is pre-installed on the VM. The Installed tools table names GCC, Clang, cmake, ninja, and conan but does not name `make`.
- Whether a Chrome or Chromium binary is pre-installed. Only `chromedriver` is listed. `dl.google.com` (Google Chrome .deb) is not on the published Trusted allowlist; Ubuntu 24.04's `chromium` apt package is a snap transition package, and snap behavior on the VM is not documented.
- Whether Puppeteer's or Playwright's browser download hosts work through the Trusted proxy (`storage.googleapis.com` is allowlisted; Playwright's CDN hosts are not in the published list).
- The exact permission scopes the Claude GitHub App requests (the app page does not list them; the docs describe capabilities, not scopes).
- Whether the GitHub proxy forwards Actions-artifact download requests (REST `/actions/artifacts/.../zip` with its 302 to an expiring URL) or `gh run download`; the docs state only that API requests to attached repositories pass and GraphQL is restricted.
- Whether the push rule ("only against the session's current working branch") permits pushing to an orphan branch checked out during the run; fetching any branch is documented as working normally.
- A maximum wall-clock duration for a single routine run. Only per-command, hook, setup-script, and idle limits are documented.
- A cap on simultaneously running sessions per account. Only hourly start limits and shared subscription rate limits are documented.
- Whether the daily routine caps from the launch post (5/15/25) still apply alongside the hourly limits in the current doc.
- The per-routine and per-account hourly caps on GitHub webhook events (stated to exist, numbers not published).
- Any way to start a routine run from `gh` other than a workflow step that curls the fire endpoint.
